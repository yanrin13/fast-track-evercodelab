# Evercode backand fast track task

backend-сервис для отслеживания и агрегации цен криптовалют с использованием CoinMarketCap API

## Архитектура проекта

Проект разделён на несколько уровней:

```text
src/
├── controllers/       # Обработка HTTP-запросов
├── services/          # Бизнес-логика
├── routes/            # REST API маршруты
├── middleware/        # Middleware. Логика авторизации
├── jobs/              # Фоновые задачи
├── db/                # Подключение и инициализация SQLite
├── utils/             # Вспомогательные функции
├── app.ts             # Создание Express-приложения
├── server.ts          # Запуск сервера
├── swagger.ts         # Swagger/OpenAPI конфигурация
├── config.ts          # Глобальная переменна задержки между запросами
└── shutdown.ts        # Корректное завершение приложения
```

`app.ts` отвечает только за создание и настройку Express-приложения.
`server.ts` отвечает за запуск приложения:

- инициализацию базы данных;
- создание пользователя по умолчанию;
- запуск фоновой синхронизации;
- запуск сервера;
- корректное завершение приложения.

Такое разделение позволяет импортировать `app` в тестах без запуска сервера и фоновых задач.

# Переменные окружения

Создайте файл:

```text
.env
```

Пример:

```env
PORT=3000
API_KEY=your_coinmarketcap_api_key
```

### Переменные

| Переменная | Описание               |
| ---------- | ---------------------- |
| `PORT`     | Порт приложения        |
| `API_KEY`  | API-ключ CoinMarketCap |

Добавьте в .env бесплатный API-ключ CoinMarketCap. Это позволит выполнять до 50 запросов в минуту

Не добавляйте `.env` в Git.

В `.gitignore`:

```gitignore
node_modules/
dist/
.env
data/
*.db
*.sqlite
*.sqlite3
```

### Настройка задержки запросов

В `config.ts` можно изменить задержку между запросами к API:

```ts
export const DEFAULT_REQUEST_DELAY = 20000; // 20 секунд
```

# База данных

Проект использует SQLite.

При запуске приложения автоматически создаются необходимые таблицы и единственный пользователь для доступа к авторизированным эндпоинтам.

Структура базы данных:

```text
users
│
├── id
├── api_key
└── created_at

coins
│
├── symbol
├── name
└── updated_at

tracked_coins
│
├── id
├── user_id
└── coin_symbol

price_history
│
├── id
├── coin_symbol
├── price
└── recorded_at
```

### Связи

```text
users
  │
  └── tracked_coins
          │
          └── coins

coins
  │
  └── price_history
```

# Фоновые задачи

Приложение автоматически выполняет две фоновые задачи

## Синхронизация списка монет

Список криптовалют синхронизируется с внешним API:

- первая синхронизация выполняется при запуске приложения
- последующие синхронизации выполняются каждый час

Синхронизация обновляет локальную таблицу `coins`

---

## Обновление цен

Актуальные цены отслеживаемых криптовалют обновляются каждые:

```text
20 секунд
```

Полученная цена сохраняется в `price_history`.

В базе данных хранится 100 монет, они обрабатываются двумя батчами по 50 монет

Таким образом, за одно обновление выполняется всего 2 запроса к API, а за минуту - 6 запросов

Это позволяет значительно снизить количество обращений к CoinMarketCap и экономнее использовать лимит API

Интервал обновления цен можно сделать меньше чем 20 секунд, установив число в `config.ts`

# Отслеживаемые криптовалюты

Для этих endpoints требуется API-ключ.
API-ключ генерируется для каждого пользователя, его можно найти в БД либо по специальному вспомогательному эндпоинту:

```http
GET /api/user/api-key
```

API-ключ передаётся в HTTP-заголовке:

```http
Authorization: Bearer YOUR_API_KEY
```

---

## Получить список отслеживаемых монет

```http
GET /api/trackedCoins
```

Пример ответа:

```json
{
  "data": [
    {
      "id": 1,
      "user_id": 1,
      "coin_symbol": "BTC"
    },
    {
      "id": 2,
      "user_id": 1,
      "coin_symbol": "ETH"
    }
  ]
}
```

---

## Добавить монету

```http
POST /api/trackedCoins
```

Тело запроса:

```json
{
  "coinSymbol": "BTC"
}
```

Успешный ответ:

```json
{
  "success": true
}
```

---

## Изменить отслеживаемую монету

```http
PUT /api/trackedCoins/:coinSymbol
```

Например:

```http
PUT /api/trackedCoins/BTC
```

Тело запроса:

```json
{
  "newSymbol": "ETH"
}
```

Ответ:

```json
{
  "success": true
}
```

## Удалить монету

```http

```

Например:


Ответ:


# Авторизация

Авторизация реализована через API-ключ.

При запуске приложения проверяется наличие пользователя в базе данных.

Если пользователей нет, автоматически создаётся пользователь с уникальным API-ключом.

API-ключ генерируется криптографически:

```text
crypto.randomBytes(32)
```

Полученный ключ необходимо использовать для запросов к endpoints, защищённым middleware `auth`.

Пример:

```http
Authorization: Bearer 0123456789abcdef...
```
